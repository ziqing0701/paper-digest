# Paper Digest

顶刊论文精读与科研训练归档站。

## 结构

- `index.html`：归档首页，只展示论文元数据和短摘要，便于搜索与筛选
- `archive.json`：论文元数据、去重记录与周报定位
- `style.css`：统一样式
- `reports/YYYY-Www.html`：每个 ISO 自然周一个完整周报，例如 `reports/2026-W41.html`

## 核心原则：索引短，正文按聊天精读原貌展开

`archive.json` 中的 `summary` 只用于首页检索，不代表精读正文。

每篇论文进入周报 HTML 后必须以聊天框中的完整精读为母版，不允许把对话内容二次压缩成摘要式模板。HTML 负责排版，内容层级、公式、数字、推导节奏和“为什么下一步必须做”都要保留。

公式使用 MathJax 渲染。所有关键机制尽量写成正式数学关系或状态链，例如 `F=k(C_w-C_{eq})`、`DFS=tr(A)`、`V=I_R-I_L`。如果公式是为了帮助理解而做的概念分解，必须明确标注 conceptual / schematic，不能伪装成论文原文公式。

每篇至少包含：

1. 完整题目、作者、期刊、年份、DOI/官方链接；
2. 一句话抓核心；
3. 研究问题，以及这个问题为什么重要；
4. 核心假设 / 物理或经济机制；
5. 数据、实验、仪器、模型或计量方法；
6. 关键结果，尽可能保留原论文中的重要数值、效应量、RMSE、相关系数或比例；
7. 最重要的 2–4 个创新点；
8. 完整科研故事线：现象/矛盾 → 科学问题 → 假设 → 证据链 → 机制验证 → 外推/闭环；
9. 为什么具备顶刊或高水平期刊录用特征：问题重要性、方法可信度、因果/机制证据、普适性、图表与叙事组织；
10. 薄弱点、识别边界和最值得继续追的问题；
11. 对用户现有科研的 1–3 个直接迁移启发；
12. 金融论文额外区分“学术结论”和“可操作投资启示”，不得把论文平均关系直接写成机械买卖信号。

## 自动化约定

同一自然周只维护一个 HTML。每次推送后：

1. 读取 `archive.json` 做 DOI / 标题 / 主题去重；
2. 检索并核验 1–2 篇高质量论文；
3. 计算 ISO 周；
4. 创建或追加 `reports/YYYY-Www.html`；
5. 周报正文按上述“完整精读版”标准写入，禁止只写简短 fact table；
6. 向 `archive.json` 添加短元数据和周报锚点；
7. `report_url` 指向周报中的对应论文锚点；
8. 首页继续保持简洁，完整内容只放在周报页。

## 叙事强制要求

完整精读必须有“层层引导”，不能只罗列九个栏目。推荐写法：

- 先指出现象或矛盾；
- 解释为什么已有解释仍不够；
- 引出下一组数据、实验或模型；
- 明确这一层结果排除了什么、还留下什么；
- 再进入下一层；
- 最后形成闭环。

每一层尽量回答一句：“为什么这里还不能停，作者为什么必须继续做下一步？”

对历史归档，若聊天中已有完整精读，应优先保留/重构原有论证顺序；以后新推送则直接把聊天精读正文同步到当周 HTML，仅做网页排版，不再重新摘要。


## 篇幅与深度下限

- 常规论文：每篇中文精读目标约 1500–2500 字；
- 特别重要、与用户研究高度相关的论文：可继续扩展到 2500–4000 字；
- 禁止为了凑篇幅加入通用套话，新增内容必须是论文特异性的；
- 每篇至少有一段“关键公式 / 变量怎么读”、一段“证据强度分层”、一段“审稿人会追问什么”、一段“如果接着做，最值得推进什么”；
- 对已有对话中已经做过详细拆解的论文，优先保留原有数字、公式、实验顺序、机制排除过程和推导节奏。
